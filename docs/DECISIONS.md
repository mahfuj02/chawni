# Decisions log

Newest last. Format: **date — decision** — reason.

- **2026-11-18 — Scaffold generated by `create-next-app` (Next.js 16.x).** Latest stable at build time.
  Its default `cacheComponents` / `partialPrefetching` flags were removed: the site is statically
  generated per locale and does not need them; they add Suspense constraints for no benefit.
- **2026-11-18 — `middleware` is named `proxy.ts`.** Next 16 renamed the convention; next-intl's routing runs there.
- **2026-11-18 — Merge commit messages are conventional** (`feat: merge feat/x`) because commitlint also guards merges.
- **2026-11-18 — `pnpm test` uses `--passWithNoTests`** only so the scaffold commit is green before tests exist.
- **2026-11-18 — `pnpm analyze` is a Node script** instead of `ANALYZE=true …`, so it works on Windows and Linux.
- **2026-11-18 — pnpm build scripts**: only `sharp` and `esbuild` are allowed to run install scripts (`pnpm-workspace.yaml`).
- **2026-11-18 — CLAUDE.md in the parent Downloads folder belongs to another project (CivicTrack)** and was not applied.
- **2026-11-18 — `loading.tsx` and `not-found.tsx` are client components** using `useTranslations`. Calling `getTranslations()` without a locale in these boundary files read request headers and silently turned every route dynamic; the client provider avoids that.
- **2026-11-18 — Projects and Journal filters read `?category=` on the client** (`useSearchParams` inside Suspense). The pages stay statically generated and the Suspense fallback is the unfiltered list, so the static HTML is complete for crawlers, while filtered URLs are still shareable.
- **2026-11-18 — Header logo uses the compact lockup at 68px wide**, below the 120px minimum in the brand rules, because the lockup is nearly square (1070×1090) and 120px would make an ~122px-tall header. The 120px minimum is respected everywhere else (footer 132px).
- **2026-11-18 — Home hero does not repeat the large logo.** The header shows the light logo on the sky-blue hero (per the brief), and the hero's right side is the 3D logo scene.
- **2026-11-18 — Journal bodies are English only.** `title_bn` and `excerpt_bn` are optional frontmatter; `/bn` article pages show an "English only" note.
- **2026-11-18 — Journal `cover` frontmatter** is either a path under `/public` (starts with `/`) or a placeholder caption, until real photos exist.
- **2026-11-18 — "What we do" pinning uses CSS `position: sticky`** instead of a GSAP pin, which is simpler, more robust with Lenis, and keeps GSAP out of pages that do not need it.
- **2026-11-18 — The contact Server Action only logs inquiries** when `RESEND_API_KEY` is unset in development, or when `CONTACT_DRY_RUN=1`. In production with no key it returns an error rather than pretending to deliver.
- **2026-11-18 — 3D capability gate.** Scenes run only when WebGL exists, `prefers-reduced-motion` is off and the device is not low-power (`hardwareConcurrency <= 4` or Save-Data). `?force3d=1` bypasses the low-power check for testing on weak machines. Otherwise the static SVG stays. In "Explore in 3D", reduced-motion and low-power users (and phones) can still start the viewer with "Load 3D view".
- **2026-11-18 — Hero pinning uses a 250svh track with a CSS-sticky stage**; GSAP ScrollTrigger (lazy-imported with the scene) only scrubs a 0..1 progress value over the ~150svh of scrolling. Space is reserved by CSS, so GSAP loading late cannot shift layout.
- **2026-11-18 — Draco decoders are self-hosted** in `public/draco/` (copied from three's examples) so GLB models do not need a third-party CDN.
- **2026-11-18 — ESLint**: React Compiler's `react-hooks/immutability` and `react/no-unknown-property` are disabled only under `src/components/three/**`, because react-three-fiber mutates three.js objects in `useFrame` and uses non-DOM props. `public/**` is ignored (vendored decoders).
- **2026-11-18 — Viewer canvas is not `aria-hidden`**, because that would also hide the keyboard-focusable photo hotspots. The decorative hero and phase canvases are.
- **2026-11-18 — Orange label colour darkened to `#B8510C`** (was `#C2560E`). The original was 4.2:1 on the mist background (fails AA for small text); the new value is 5.1:1 on white and 4.6:1 on mist. `--color-orange` (`#F47C24`) is unchanged.
- **2026-11-18 — Initial JS budget.** Measured as the gzipped, non-`nomodule` scripts referenced by each page's HTML: 172–188 KB for every page without 3D (budget 200 KB). Achieved by (1) lazy-loading the mobile-menu dialog on first interaction, (2) importing Lenis after hydration, (3) code-splitting the contact form and loading zod only when a field is focused or the form is submitted. Next's `nomodule` polyfill chunk (~39 KB) is excluded because modern browsers never download it.
- **2026-11-18 — OG images use English titles in both locales**: the default OG font has no Bengali glyphs, and shipping a Bangla font file only for social cards was not worth the weight.
- **2026-11-18 — Performance work for Lighthouse mobile.** Applied: next-intl message precompilation (`experimental.messages.precompile`, -8 KB gz), only the namespaces client components use are sent to the browser, `Reveal` is now pure CSS (scroll-driven `view()` timeline, no JS, content stays visible where unsupported), `WhatWeDo` is code-split so React hydrates it in its own time-sliced work, only the fonts a page needs are preloaded (Hind Siliguri `preload: false`, Inter as one variable file), the hero 3D scene starts on first user interaction (static SVG until then), the WebGL probe runs only right before a scene mounts, and `Array`-heavy work stays out of start-up.
- **2026-11-18 — Lighthouse reality check.** Measured locally (Windows, Chrome headless with a software GL renderer, default mobile simulation): accessibility 98–100, best-practices 100, SEO 100. Performance varied run to run on the same build: Contact 81–90, Projects 83–87, Home 62–79. The residual cost is the framework baseline (react-dom + Next router ≈ 110 KB gz) and hydration under Lighthouse's 4x CPU throttle: observed (unthrottled) FCP/LCP are ~0.5 s. Re-measure on the deployed site (Vercel) before treating these as final.
- **2026-11-18 — `loading.tsx` lives only on leaf routes** (`about`, `services`, `contact`, `privacy`) and shares one `PageSkeleton`. A `loading.tsx` at `[locale]` wrapped the catch-all and the `[slug]` routes, so `notFound()` ran after the response had started streaming and unknown URLs returned **HTTP 200** (a soft 404). Found by the Playwright 404 tests; with the boundary removed they return a real 404.
